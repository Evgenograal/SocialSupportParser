**SocialSupportParser**

SocialSupportParser - настольное приложение на Python для автоматизированного извлечения сведений о мерах социальной поддержки из текстовых документов с помощью языковой модели. Программа обрабатывает исходные файлы, формирует структурированные данные в формате JSON, позволяет повторно запускать обработку файлов с ошибками, объединять результаты с исходными Markdown-документами и просматривать полученные JSON-файлы.

**Возможности**
- Пакетная обработка документов. Рекурсивный поиск файлов .md и .txt во входной папке и отправка их содержимого языковой модели.
- Извлечение структурированных данных. Модель получает инструкцию из шаблона промпта и справочники категорий, жизненных ситуаций, семейных статусов и территорий. Ответ сохраняется в JSON.
- Параллельная обработка. Количество одновременно выполняемых задач задаётся параметром max_workers.
- Повторная обработка ошибок. Программа анализирует лог предыдущего запуска и повторно обрабатывает документы, завершившиеся ошибкой.
- Объединение JSON с Markdown. JSON-файлы сопоставляются с .md-документами по имени файла и копируются рядом с соответствующими Markdown-файлами.
- Просмотр JSON. Дерево файлов и вложенной структуры JSON с поиском по значениям.
- Настройка модели и справочников. Через интерфейс можно менять модель, API-параметры, промпт и справочные значения.
- Журналирование и прогресс. Во время выполнения отображаются ход обработки и сообщения о результатах.

**Технологии**
- Python 3.10 или новее (рекомендуется Python 3.11+).
- PyQt5 — графический интерфейс.
- PyQtDarkTheme (qdarktheme) — тёмная тема.
- OpenAI Python SDK — взаимодействие с API, совместимым с OpenAI Chat Completions.
- concurrent.futures, threading, json, os и другие стандартные библиотеки Python.

**Настройка**

Основная конфигурация хранится в data/settings.json. В проекте также присутствует data/default_settings.json с настройками по умолчанию.

Основные параметры:
Параметр	Назначение
model	Идентификатор используемой языковой модели
base_url	Адрес API, совместимого с OpenAI API
api_keys	Список API-ключей для запросов
max_retries	Максимальное количество попыток запроса к модели
max_workers	Количество параллельно обрабатываемых файлов
request_delay	Пауза после успешной обработки файла
categories	Список категорий мер поддержки
life_situations	Список жизненных ситуаций
family_statuses	Список семейных статусов
territories	Список территорий и организаций


Шаблон инструкции для модели находится в data/default_prompt.txt. В нём используются подстановки {categories}, {life_situations}, {family_statuses}, {territories} и {text}. Текущий промпт и справочники можно редактировать во вкладке «Настройки».

****Безопасность** API-ключей:**
Не публикуйте data/settings.json, не добавляйте реальные ключи в Git и не отправляйте их в открытые архивы. Для публичного репозитория используйте пустой список ключей или переменные окружения/локальный конфигурационный файл, исключённый из системы контроля версий. Если ключ уже попал в опубликованный архив или репозиторий, отзовите его у провайдера и создайте новый.
Сейчас написанные ключи недействительны, поэтому Вам необходимо заменить на свои.

**Работа с приложением**

_1. Обработка документов_
1. Откройте вкладку «Обработка».
2. Выберите папку с исходными .md и/или .txt файлами.
3. Укажите папку для результатов. Если её не указать, приложение создаст json_output внутри исходной папки.
4. Нажмите «Запустить».
5. Следите за прогрессом и сообщениями в журнале.
Структура вложенных папок исходного каталога сохраняется в каталоге результатов. Для каждого успешно обработанного документа создаётся JSON-файл с тем же именем. В каталоге результатов также формируется progress_log.txt.

_2. Повторная обработка_
1. Перейдите во вкладку «Повторная обработка».
2. Укажите исходную папку с документами и папку результатов.
3. Выберите лог предыдущего запуска (progress_log.txt).
4. Нажмите «Повторная обработка».
Программа находит в журнале записи об ошибках, ищет соответствующие исходные файлы и запускает их обработку повторно. Для повторного запуска создаётся retry_log.txt; документы, которые снова не удалось обработать, копируются в failed_files_retry.

_3. Объединение JSON с MD_
1. Откройте вкладку «Объединение JSON с MD».
2. Выберите папку с Markdown-документами.
3. Добавьте одну или несколько папок с JSON-результатами.
4. Нажмите «Объединить».
Сопоставление выполняется по имени файла без расширения. Найденный JSON копируется в папку соответствующего .md-файла. Если совпадение не найдено, это отражается в журнале.

_4. Просмотр JSON_
1. Откройте вкладку «Просмотр JSON».
2. Выберите папку с JSON-файлами.
3. Выберите файл в дереве слева, чтобы увидеть его структуру справа.
4. Используйте строку поиска для фильтрации элементов JSON.

_5. Настройки_

Во вкладке «Настройки» доступны параметры модели и API, управление ключами, редактирование справочников и промпта, проверка API, импорт и экспорт настроек, а также сброс к значениям по умолчанию.
Форматы входных и выходных данных
- Входные документы: .md, .txt (UTF-8).
- Результат обработки: .json (UTF-8, кириллица сохраняется без ASCII-экранирования).
- Журналы: .txt.
- Объединение: JSON копируется рядом с одноимённым Markdown-файлом; содержимое Markdown не преобразуется.
Структура итогового JSON определяется шаблоном промпта и ответом выбранной модели. Для стабильного результата рекомендуется проверять промпт и просматривать сформированные JSON-файлы перед использованием данных.

**Примечания**
- Для работы обработки требуется доступ к выбранному API-провайдеру и действующий API-ключ.
- Параметр max_workers влияет на число одновременных запросов и может приводить к ограничениям по частоте запросов со стороны провайдера.
- Обработка выполняется с учётом лимитов API; при ответах с ограничением частоты запросов клиент делает повторные попытки с увеличивающейся задержкой.
- Перед массовой обработкой рекомендуется проверить работу на небольшой тестовой папке.
